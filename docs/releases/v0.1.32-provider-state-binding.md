# v0.1.32：渠道 Provider 与 Responses 连续对话状态绑定

日期：2026-09-21

## 目标与适用场景

同一模型通过 OpenAI、Azure 等不同来源提供服务时，普通文本可以按既有规则路由；携带 thinking/reasoning 或 compaction 加密历史的请求，需要回到兼容的来源。仅限制一次请求的重试不足以保护下一轮对话，因此同时约束首次选渠和失败重试。

本实现以管理员确认的“同 Provider 资源互通”为前提。Provider 是自定义兼容性标识，不根据渠道类型自动推断，也不保证不同账户、部署或模型天然互通。

## 最终行为

| 场景 | 路由规则 |
| --- | --- |
| 普通文本，没有历史状态和显式 Provider 头 | 首次选渠沿用权限、模型、优先级、权重和亲和规则 |
| 首次渠道配置了 Provider | 本次失败重试只能选择相同 Provider；候选耗尽即失败 |
| 已知 reasoning/compaction 密文 | 后续首次选渠与重试限定原 Provider |
| previous_response_id、conversation、item_reference | 固定原渠道及密钥 |
| reasoning/compaction 只有 ID，没有密文 | 固定原渠道及密钥 |
| 历史来源未配置 Provider | 固定原渠道及密钥 |
| 多份历史来源冲突 | 明确拒绝，不删除状态继续执行 |
| 历史来源未知或过期 | 明确拒绝；加密历史可由客户端显式指定原 Provider |
| 普通请求首次渠道未配置 Provider | 保留原有重试行为；建议为相关渠道全部配置 Provider |

绑定依据请求携带的上游状态，不依赖额外会话 ID。纯文本请求不会因为之前属于某个对话而永久绑定。

## 前端配置

仓库：`linkinfra-web`。

渠道表单增加可选 `Provider` 输入框，支持新建、编辑回显、批量创建及清空。最长 128 个字符，通过现有渠道 `config` JSON 保存。后端匹配时忽略首尾空格及大小写。

```json
{"provider":"openai"}
```

```json
{"provider":"azure","api_version":"2025-04-01-preview"}
```

通过 API 更新时应合并保留原 config 的其他字段。多 key 渠道内的所有密钥也应属于同一兼容来源。无需增加数据库表或迁移字段。

## 后端实现

1. **重试边界**：首次选渠后保存 Provider 约束，候选过滤覆盖 response-id 缓存、亲和候选及不同优先级的渠道。仍执行模型、用户组、渠道状态等原有检查；受约束的候选耗尽后不循环失败列表或回退最后渠道。
2. **状态索引**：响应返回前记录 reasoning/compaction 密文指纹、item ID、response ID、conversation ID 的来源。普通响应和 SSE 事件均支持，不要求等到 response.completed 才记录。
3. **跨轮恢复**：在 `/v1/responses` 和 `/v1/responses/compact` 首次选渠前解析历史引用，查索引并设置路由边界。
4. **资源引用**：服务端引用额外验证渠道、key 索引及 key 指纹；原 key 禁用、更换或失效时拒绝静默换 key。
5. **内容完整性**：不剥离 encrypted_content，不删除 reasoning/compaction，不清理工具调用与结果。模型映射只替换 model，保留未知字段、显式 false/0 与大整数。
6. **流式异常**：上游确认前禁用预请求 ping，避免提前提交 HTTP 200；流开始后不重放请求。状态缓存失败不自动禁用上游渠道；首事件前失败清除 SSE 头并返回 JSON 错误，流已开始则发送明确错误事件。
7. **Azure 路径**：保留 compact 后缀，映射为 `/openai/responses/compact?api-version=...`，版本沿用渠道配置。

## 缓存与升级

- 索引 key 由用户 ID、引用类型及值计算 SHA-256，按认证用户隔离。
- 只保存来源元信息和指纹，不保存对话正文、密文或密钥明文。
- 默认 TTL 为 7 天，读取命中续期。
- 已启用 Redis 时使用共享索引；Redis 故障明确失败，不降级为不一致的本地状态。
- 未启用 Redis 时使用最多 100000 项的进程内缓存。重启、淘汰或过期会失去来源记录；多实例必须配置共享 Redis 才能稳定跨实例恢复。
- 升级前的历史没有新索引。对已确认来源的加密历史，可在请求中持续携带 `X-Linkinfra-Provider: openai` 或 `azure`；仅指定该头不保证旧历史被永久导入索引。
- Provider 头不能覆盖已知冲突来源，不能定位未知服务端引用；仍受模型和用户组权限约束。未知服务端引用需要恢复完整可携带历史或新建会话。
- 索引查询/历史冲突在分发阶段返回 409；没有可用兼容渠道返回 503；响应状态记录失败在尚未输出时返回 503，已输出时通过 SSE 错误通知。

## 复用时的文件入口

| 模块 | 文件 |
| --- | --- |
| 渠道配置、Provider 与资源边界 | `model/channel.go`、`model/channel_provider.go` |
| 候选过滤 | `model/cache.go` |
| 首次选渠、密钥恢复、亲和检查 | `middleware/distributor.go` |
| 重试停止条件与错误返回 | `controller/retry_policy.go`、`controller/relay.go` |
| 状态识别、索引读写 | `service/responses_state.go`、`service/responses_state_store.go` |
| 普通与 SSE 响应处理 | `relay/controller/opeai_response.go` |
| 保留请求字段的模型映射 | `relay/controller/responses_request.go` |
| Azure compact URL | `relay/channel/openai/adaptor.go` |
| 前端表单 | `linkinfra-web/sections/channel/channel-form.tsx` |

移植到其他网关时应保留四个接入点：首次选渠前恢复状态来源、所有候选选择执行相同边界、输出状态前记录来源、流开始后禁止重试。仅移植前端字段或单个重试过滤器不足以保护连续对话。
