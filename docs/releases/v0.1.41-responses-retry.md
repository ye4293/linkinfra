# v0.1.41：Responses 渠道路由与重试诊断

## 问题与变化

response ID 和规则亲和命中时，旧内存缓存可能继续返回已禁用的渠道。现在缓存仅提供偏好，渠道配置与状态从数据库重新读取；失效亲和同时清除旧 key 索引和禁止重试标记。

Responses 的正常重试选择器已负责优先级降级和允许范围内的循环，选渠失败后不再额外复用旧渠道对象。保留单请求聚合日志：所有真实尝试仍写入 `retryHistory`，最后一次失败追加 `stop_reason`，不伪造未发出的尝试。日志 key 索引来自实际选择，不再为了日志额外轮转 key。

流扫描器使用独立广播通知主请求结束，避免 ping 协程消费完成信号后主请求等待到超时才记录日志。扫描协程启动前注册 WaitGroup，扫描与 ping 的退出清理结束后才释放计数。

历史状态/provider 兼容边界保持原有约定。已经输出流内容的请求不会自动重放；HTTP 429 和首事件 429 在存在兼容备用渠道时正常重试。
