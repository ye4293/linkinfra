# v0.1.46 渠道计费标签

日期：2026-11-12。分支：`main`。上一发布版本：`v0.1.45`。

## 修改内容

- 渠道 `config` 新增可选的 `billing_tag`，用户折扣 `users.channel_ratios` 新增 `tag:<标签>` 项。渠道有标签且用户配置了该标签的折扣时用标签折扣，否则用渠道类型折扣，都没有则为 1.0。标签折扣覆盖类型折扣，两者不相乘，计费公式不变。同一渠道类型下的不同渠道（如 Vertex AI 的 Gemini 与 Claude）因此可以对同一用户设置不同折扣。
- 标签只用于计费和统计，不参与选渠、失败重试和 Responses 状态绑定。失败重试换了渠道后，折扣按最终成功的渠道取值。
- 新增 `GET /api/channel/billing_tags`（管理员），返回渠道上现有的标签和渠道数。
- 不合法的标签在保存渠道时拒绝。保存用户时校验 `channel_ratios`：key 只能是渠道类型或 `tag:<标签>`，值必须是数字。请求里不带该字段（或值为 `null`）时不再清空已有折扣。
- 文本对话、Claude Messages、Gemini 原生、Responses 和 System One 的消费日志在折扣来自标签时记录 `billing_tag`。用户查询自己的日志和资料时不返回标签。
- 管理员总览 `/api/dashboard/stats` 新增 `source_stats`：最近 24 小时的消耗，打了标签的渠道按标签归组，其余按渠道类型归组，已删除的渠道合并为一项。
- 用户折扣的 Redis 缓存改用 key `user_channel_ratios:v2:<用户 id>`。

使用说明见[渠道计费标签](../billing-tag.md)，方案见[实施计划](../plans/2026-11-11-billing-tag-user-discount.md)，逐条改动见[变更记录](../CHANGELOG.md)。

本次包含 `31751d1`（计费标签与按标签的用户折扣）、`88f28bb`（按来源的 24 小时消耗）、`f1ca094` 和 `26ac5f9`（发布前审查的修复）、`9f91af3`（补测试）、`0fdaec1`（第二轮复核的修复）。无数据库迁移。前端在 `ye4293/linkinfra-web`，对应提交 `054c0ff`、`a037efa`、`93e19e6`、`08f852e`、`3f69c41`，说明见该仓库的 `docs/releases/2026-11-12-billing-tag.md`。

第一轮已修复（后端 `f1ca094`、`26ac5f9`，前端 `93e19e6`）：

- 标签的读取依赖整份 `config` 解析成功。`config` 的其他字段类型不对时（例如 Vertex 区域映射被存成字符串），渠道照常转发，标签却被当成未配置，标签折扣和按标签的统计静默失效。现在只解析 `billing_tag` 一项。
- `billing_tag` 不是字符串时通过了保存校验，保存后整份 `config` 解析报错，连 Provider 也读不出来。现在保存时拒绝。
- 标签名先转小写再校验，个别非 ASCII 字符（如开尔文符号）会被折叠成合法的 ASCII 标签。现在按 ASCII 逐字节校验。
- 新旧版本共用一个 Redis key：旧版本写入的缓存不含标签折扣，新版本读到后标签折扣在缓存有效期内失效。现在新版本使用新的 key。
- 保存用户时不校验 `channel_ratios`：有一项的值不是数字会让计费侧整份作废，渠道类型折扣一起失效。请求里不带该字段时会清空已有折扣。现在保存时校验，缺字段时不改动。
- `/api/user/self` 在原文里找 `tag:` 字样来去掉标签项，key 用 JSON 转义书写时标签名会返回给用户本人。现在用计费的同一个解析器，只输出渠道类型折扣。
- 用户日志去掉 `billing_tag` 的正则作用于整段内容，其他段里出现同样字样时真正的标签会留下来；JSON 格式只处理了一种写法。现在只处理计费明细段，并覆盖 JSON 格式的几种写法。
- 来源统计的查询失败会让整个总览接口失败。现在只记日志，其余统计照常返回。
- 同步选渠和异步结算各有一份取值逻辑；`model/user.go` 里留着只认渠道类型、回写会抹掉标签项的旧方法。现在共用 `model.ResolveUserChannelRatio`，旧方法删除。
- 前端折扣编辑器：不可用的输入（0、负数、没输完的数字）被悄悄丢弃并按旧值保存；批量框和搜索框按回车会提交整个用户表单；三位小数被浏览器的步长校验拦住；名为 `constructor` 的标签不显示；名为 `target` 的 key 会让一次编辑清空全部折扣；标签名的识别口径与后端不一致。

第二轮已修复（后端 `0fdaec1`，前端 `08f852e`）：

- 保存用户时放行了计费不认的 key。漏写 `tag:` 前缀的标签名（如 `{"vertex-claude":0.85}`）和 `" 48"`、`"48.0"`、`"0"` 这类 key 能保存，计费时被忽略，填的折扣不生效也没有提示。现在保存时拒绝并指出是哪个 key。
- `PUT /api/user/` 里 `channel_ratios` 为 `null` 会清空折扣。现在按没有提交处理；同一个 key 出现两次、后一次是 `null` 时，先解析出的值也不能绕过校验写库。
- 来源统计查询失败时，缺了来源的总览结果会被缓存 10 分钟。现在不写入缓存，下一次请求重新查询。
- 保存折扣后清缓存、`channel_ratios` 字段名不区分大小写、折扣缓存带过期时间，这三处改坏了测试也照样通过。现在各有测试守住。
- 前端折扣输入框是数字框，上一轮把步长放开之后，方向键、滚轮和步进箭头一次改 1（0.85 变成 1.85），改出来的是合法折扣，会随 Save 保存。现在改为文本框，只认普通的十进制写法。
- 前端 `-`、`.` 这类没输完的内容一步删空后，这一行卡在“空输入框加报错”，Save 一直被拦住。改为文本框后可以正常删除。
- 前端有无效输入的行被卸载时（切到 Basic info 页签，或被搜索、Customized only 筛掉），输入和它对保存的拦截一起消失，Save 按旧值提交且没有提示。这一条在上一轮之前就有。现在未生效的输入由编辑器统一保存，折扣页签切走后保持挂载，保存被拦住时切回折扣页签显示是哪一行。

第二轮指出、只写进文档的一条：滚动发布期间旧版本实例保存的折扣改动只清旧的缓存 key，新版本实例最长陈旧一个 `SYNC_FREQUENCY`。见下面的“上线注意”。

确认、本次不改，已写入[渠道计费标签](../billing-tag.md)：

- 通过 API 更新渠道时 `config` 传空字符串不生效（空值在更新时被跳过）。改后端语义可能让其他 API 客户端误清配置；前端改为没有配置项时提交 `{}`。
- 图片、音频和 Flux 的消费日志没有计费明细，看不到命中的标签，扣费额是对的。
- 视频、异步图片、Recraft、OCR 和 xAI 内容违规固定扣费本来就不乘用户渠道折扣，标签折扣在这些路径上同样不生效。
- 开启渠道内存缓存时，“重试时选不到其他渠道、回退到上一个渠道”这条路径在下一次缓存同步前按旧标签取折扣。
- 总览的各项统计都包含渠道测试写入的消费日志；来源统计按渠道当前的标签归组，不是请求发生时的快照。

确认、本次不改，影响很小或与本功能无关：

- Flux 异步结算传入的渠道类型写死为 Flux（既有行为）。Flux 模型挂在其他类型的渠道上时，回落用的是 Flux 类型的折扣；标签取自渠道本身，不受影响。
- `source_stats` 里渠道类型为 0 的项没有 `channel_type` 字段。这类渠道在管理界面里建不出来，展示名照常返回。
- 每次选渠多解析一次渠道 `config`（微秒级）；总览冷刷新多一次日志聚合（每个实例最多每 10 分钟一次）。
- `PUT /api/user/` 不带 `quota` 的局部更新会写一条“额度从 X 改为 0”的管理日志，实际额度没有变（既有行为，前端总是带上 `quota`）。
- 折扣值没有上限（既有行为）：填 `85` 会按 85 倍计费，前后端都不拦。
- 库里的折扣值如果被直接写成了字符串（如 `{"48":"0.9"}`），计费侧整份作废，而管理界面仍显示 0.9。新版本的保存接口已经拒绝这种写法，只可能是历史数据或直接改库。
