# v0.1.47 等级改为四档（代码部分）

日期：2026-11-12。分支：`main`。上一发布版本：`v0.1.46`。

## 修改内容

- 等级名不再写死在代码里。新用户的默认分组，以及 Flux 结算时取不到用户分组的兜底分组，改为取 `group_configs` 里升级门槛最低的一档（并列时取 `sort_order` 小的，再并列取 `id` 小的）；表为空时回退到 `Start`。`users.group` 的 GORM tag 没有改，这次发布不会让 AutoMigrate 改动 `users` 表。
- 文件上传的容量上限改为按所在等级的升级门槛分档：门槛不低于 $250 是 2GB，不低于 $100 是 1GB，不低于 $50 是 500MB，不低于 $5 是 300MB，其余 100MB。分组不在 `group_configs` 里时按 100MB。
- `GET /api/group` 返回的分组集合不变，顺序改为按 `group_configs.sort_order`，不在表里的排在后面。
- 全新部署的默认等级改为 Start / Build / Scale / Enterprise，门槛 $0 / $50 / $300 / $1000。已有的库不受影响。
- 新增把已有的库从 Lv1–Lv6 迁到四档的脚本和上线手册，在 `scripts/migrations/2026-11-12-tier-rename.*`；验证脚本是 `scripts/verify-tier-rename.pg.cjs`。**这次发布不执行数据迁移**，迁移在全部实例升级之后单独进行。

本次包含 `b6c41a7`。没有数据库结构变更，前端不用改。方案见[实施计划](../plans/2026-11-12-tier-rename.md)，迁移步骤见[上线手册](../../scripts/migrations/2026-11-12-tier-rename.pg.md)，逐条改动见[变更记录](../CHANGELOG.md)。

## 上线注意

- 发布后、数据迁移前，等级、折扣、返现和可用渠道都和之前一样。新旧版本的实例可以同时运行。
- 发布后立刻生效的变化只有两处：
  - 文件容量按门槛分档。升级门槛被改过的库，部分旧等级的上限会变大；Lv6 从一律拒绝变成 2GB；不在等级表里的分组从一律拒绝变成 100MB。
  - `GET /api/group` 的顺序。
- 数据迁移必须等全部实例都升级到本版本之后再做。旧版本不能配迁移后的库：它给新用户填的默认分组是 `Lv1`，迁移后这个分组没有任何可用渠道。
- 迁移当时的顺序：停后端 → 执行迁移 → 删除 Redis 里的 `user_group:*` → 启动后端。不重启的话，实例内存里的渠道缓存和分组倍率最长要 `SYNC_FREQUENCY` 秒才更新，这期间会有请求找不到可用渠道。
- 回滚到 `v0.1.46`：数据迁移之前可以直接回滚。数据迁移之后不能只回滚代码，要先用回滚脚本把数据恢复成六档。
- 不经过后端、直接用 SQL 插入用户时要显式填写 `group`：这一列在数据库里的默认值仍是 `Lv1`。
