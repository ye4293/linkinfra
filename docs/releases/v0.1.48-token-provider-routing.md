# v0.1.48 令牌的来源路由与 provider 互通规则

日期：2026-11-26。分支：`main`。上一发布版本：`v0.1.47`。

## 修改内容

- 令牌新增可选的来源路由，存在新列 `tokens.provider_routing`（JSON 文本，没有设置时为 NULL）。用户在 API key 上决定请求可以使用哪些上游来源（`config.provider` 的值，没填 provider 的渠道按渠道类型名）、使用的先后顺序、是否只用选中的来源（`only`），以及永不使用的来源（`ignore`）。没有设置路由时，选渠和重试与之前完全一致。
- 首次选渠按路由分层：`order` 里每个来源一层，`only` 为 false 时其余来源合并为最后一层；前面的层没有可选渠道才进入后面的层。层内沿用管理员的优先级和权重。失败重试使用同一个顺序。
- 新增系统设置 `ProviderInteropRules`（JSON 数组，每条规则是一组模型正则和一组 provider）。请求的模型和首选渠道的 provider 命中某条规则时，本次请求的失败重试范围扩大为这条规则列出的一组 provider。带 Responses 历史状态或 `X-Linkinfra-Provider` 请求头的请求不扩大。保存时校验，不合法时拒绝并把当前生效的规则保持不变。
- 重试范围里有多个来源时，失败渠道按来源分别汇总，降档规则（原档补重试一次，之后只往更低的优先级）分别计算。范围只有一个来源时与之前完全相同。
- 跨 provider 重试后因为不可重试的错误停止时，返回首次尝试的错误而不是后一个 provider 的错误；后者的错误保留在错误日志的重试明细里。
- Responses 状态记录的来源在重试范围被扩大时改为实际处理请求的渠道的 provider。亲和缓存对设置了路由的令牌按令牌分别记录（key 里加 `token=<id>`）。
- 用户日志和管理员日志返回新的 `source` 字段（处理请求的渠道的来源名，不落库，按需从渠道当前配置取）。新增 `GET /api/token/sources`（令牌表单的来源选项）和 `GET /api/channel/providers`（管理员，渠道上已配置的 provider 及渠道数）。
- 保存渠道时校验 `provider`：必须是字符串且不超过 128 个字符。
- 令牌的 Redis 缓存改用 key `token:v2:<key>`，更新和删除令牌时清除（新旧 key 都清）。

使用说明见[令牌的来源路由](../token-provider-routing.md)，方案见[实施计划](../plans/2026-11-25-token-provider-routing.md)，逐条改动见[变更记录](../CHANGELOG.md)。

## 数据库

新增一列 `tokens.provider_routing`（TEXT，可为 NULL），由 GORM 的 AutoMigrate 在 `NODE_TYPE=master` 的节点上创建。没有其他结构变更，不需要数据迁移。

发布期间如果某个实例先于主节点启动、那一列还不存在：

- 创建没有设置路由的令牌不受影响（不写这一列）。
- 查看、编辑和删除现有令牌也不受影响。
- 只有在这个实例上给令牌设置来源路由、或查询令牌列表时会报错。等主节点加上列之后自动恢复。

## 上线注意

- **后端全部实例先升级，再发布前端。** 新前端遇到旧后端时路由区域不会显示；旧前端遇到新后端时会把读到的 `provider_routing` 原样带回，后端按没有修改处理（有接口测试）。前端已经在 2026-11-26 上线，所以现在上线后端即可让功能生效，前端不需要再发一次。
- 新列由 `NODE_TYPE=master` 的节点创建。只有这个角色的节点执行 AutoMigrate。
- 滚动发布期间，新旧实例共用同一个数据库，但令牌缓存 key 不同（`token:v2:` 与 `token:`）。在旧实例上改令牌不会清掉新实例的缓存，最长 `SYNC_FREQUENCY` 秒内新实例可能还读到旧的路由。全部实例升级后不再有这个问题。
- 没有配置互通规则时，重试行为与 `v0.1.47` 完全相同。规则只影响失败重试的范围，不影响首选渠道。
- 规则只声明“这些 provider 之间可以互相重试”。OpenAI 与 Azure 的 reasoning 密文、AI Studio 与 Vertex 的 Gemini thought signature 不互通，不要写进同一条规则。
- 渠道上的 provider 改名会让引用旧名字的令牌设置和互通规则失效。要改就先清掉引用，改完再重新配置。
- 回滚到 `v0.1.47`：令牌表多出一列，旧版本不读它，可以直接回滚。回滚之后令牌的来源路由和互通规则都不再生效，令牌缓存回到旧 key（`token:`）。旧版本读不到新版本写入的 `token:v2:`，遇到这种情况直接读库；回滚后的第一个同步周期内，旧 key 里可能还是升级前的内容，状态和额度最长 `SYNC_FREQUENCY` 秒后才刷新，与平时的缓存行为一致。
