# 模型广场按渠道独立展示

## 背景与目标
用户明确要求同名模型不跨渠道合并，各渠道独立展示、计数和计算折扣。千帆条目保留在 Baidu 分类，自有渠道保留各自分类，替代前一次将千帆模型转归原厂商的修复方案。

## 方案设计
- 后端目录以渠道 ID 和模型名共同标识条目，去重仅限单渠道内部；稳定排序后分页。
- 返回渠道 ID，使用该渠道折扣。详情价格支持渠道 ID；未指定渠道且同名存在多条时不任意选择价格。
- 前端模型广场、首页使用复合标识与带渠道参数的详情链接，修正首页二次去重与侧栏全部计数。
- 监控仍为现有模型总体统计，界面标注统计范围；不扩展监控存储或调用路由。
- 涉及 common/model-provider.go、controller/model_plaza.go、controller/model_metrics.go、controller/qianfan_test.go，以及关联前端目录类型、首页目录工具、首页、模型广场和详情组件、目录测试。

## 影响范围
仅目录展示与价格选择，无数据库迁移，不修改渠道配置或实际请求分发。公开渠道 ID 用于标识目录条目，不返回内部渠道名、密钥或上游地址。

## 验证方式
后端验证跨渠道同名保留、单渠道重复清理、厂商计数、独立折扣、详情选择、分页稳定、禁用渠道过滤；前端验证跨页同名条目保留和详情链接。执行 Go 回归、隔离工作树完整 build/vet、前端类型检查及目录测试。
