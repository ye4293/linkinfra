# 密码注册强制邮箱验证

问题：邮箱验证默认关闭时，公开注册接口接受纯账号密码；邮箱验证码可重复使用，注册时没有再次查重。

实施：
- 密码注册必须提交合法邮箱和邮箱验证码，与旧验证开关无关。
- 旧配置加载为强制开启，管理接口拒绝关闭，状态接口始终告知前端需要验证码。
- 发码和注册共用邮箱格式、长度及现有域名白名单校验。
- 邮箱验证码验证与消费在同一把锁内完成；错误尝试达到 5 次失效。绑定邮箱同步使用一次性验证。
- 注册、发码和绑定邮箱按忽略大小写的方式查重，数据库查询失败时拒绝继续。
- 注册、发码、绑定邮箱及配置校验的用户提示统一为英文，验证码邮件使用英文说明有效期及一次性使用规则。

验证：覆盖缺邮箱、缺验证码、伪造/过期验证码、并发重放、重复邮箱、旧配置、白名单和合法注册，运行 Go 测试、编译和静态检查。

本地验证结果：`go test ./common ./controller ./model`、`go build ./...`、`go vet ./...` 均通过。SQLite C 依赖有已有的编译警告。尚未部署，也未发送真实测试邮件。

上线说明：
- 需要配置 Resend API key、发件地址和 Resend 已验证域名；邮件服务不可用时，用户无法完成密码注册，不会退回无邮箱注册。
- 前端继续使用 GET /api/verification?email=... 获取验证码，POST /api/user/register 提交 username、password、email、verification_code。
- 现有登录和第三方 OAuth 流程不变，无数据库结构迁移，也不清理已有账户。
- 验证码仍沿用进程内存存储，多实例部署需要会话粘滞或后续接入共享验证码存储。
- 此变更阻断无邮箱和验证码重放注册；持有大量真实邮箱的攻击仍建议结合已有 Turnstile、人机验证和域名白名单限制。
