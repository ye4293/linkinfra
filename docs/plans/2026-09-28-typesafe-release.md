# TypeSafe 最终验收与发布

## 目标
按用户授权，从渠道创建到客户端调用完成最终审查，验证通过后发布 GitHub tag 并确认工作流。

## 范围
- 隔离发布分支合并 origin/main 的 v0.1.36～v0.1.38 消息协议修复，不改动用户未提交文件。
- 使用真实管理 API、鉴权、渠道数据库、模型发现、后台测试和客户端 /v1/systemone 入口进行端到端验证；业务余额与日志使用内存数据库。
- 使用已有授权的 TypeSafe 密钥进行最小在线验收，密钥仅在测试进程环境中使用。
- 全量后端 test/build/vet、相关 race；前端最终源码生产构建和渠道表单检查。
- 后端 main 与 v0.1.39 发布 tag，前端 main 与对应发布 tag；检查 GitHub Actions/部署状态。用户已授权推送与触发更新。

## 发布边界
发布流程构建镜像并创建 GitHub Release；不能把镜像构建成功等同于生产机器已拉取重启。TypeSafe 接入无需 schema 迁移；已有来源监控 V2 保持默认关闭，不自动开启。
