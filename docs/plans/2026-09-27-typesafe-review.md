# System One 计费、响应与错误审查

## 目标
按用户要求审查并修复 TypeSafe 接入中的边界问题，不操作业务数据库。

## 方案
- 先补测批量更新时预扣是否落库、数据库更新中途失败是否回滚、请求期间改价、零用量日志、不完整答案和非 JSON 错误。
- 将现有音频事务额度操作提取为通用事务辅助函数，System One 使用原子预扣、退款和结算；结算失败显式返回错误并禁止自动重试。
- 请求开始冻结价格及折扣，结果日志复用既有格式。校验返回答案对应全部请求问题、类型和基本值。
- 统一 TypeSafe 原生错误解析，保留 Retry-After；限制 System One 的 xAI 特殊扣费分支，修正跳过重试时的响应。
- 回归后台渠道测试、原有音频额度逻辑与通用 relay。

## 影响
不改变其他协议价格逻辑，无 schema 迁移。System One 的余额操作使用即时事务，不受批量更新设置影响。

## 验证
内存 SQLite 故障注入和并发预扣，模拟上游响应与路由重试，针对性 race 检测；相关包回归及隔离源码完整 build/vet。生产 PG/MySQL 行为不以 SQLite 测试替代。

## 推送前复审
- 检查切换渠道后的自定义请求头清理、退款后的令牌耗尽状态恢复及并发状态更新。
- 后台渠道测试采用与业务请求相同的答案校验，异常 3xx 不能透传成无正文的错误响应。
- 补充复现测试，最终提交在隔离源码目录执行全量测试、build/vet 和针对性 race。
