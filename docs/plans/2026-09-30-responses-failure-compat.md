# Responses 失败事件兼容修复与发布前验收

用户已要求修复并本地验证；完成后追加授权打 tag、推送 GitHub 并触发镜像打包。最终发布版本为 v0.1.40。

## 目标与方案

修复验收发现的数字错误码和空错误对象透传问题。仅将字段有效的上游 `response.failed` 原样透传；异常失败事件原位规范化，保留 response id、sequence_number 及扩展字段，只输出一个终止失败事件。其他流中止与缓存故障继续使用现有错误路径。

涉及 `relay/controller/responses_error.go`、`opeai_response.go` 及错误回归测试；补充路由生命周期测试，更新 CHANGELOG、故障文档与验收报告。无数据库迁移，无生产配置修改。

## 验证

先用实际 SSE 解码断言复现数字错误码、空对象、缺失/null/空白字段等失败，再修复。验证合法事件原样保留、非字符串规范化、唯一终止事件及序号/扩展字段保留。使用本地 HTTP 上游和内存数据库验证失败请求不扣费、不重放、只写错误日志。最终在包含所有当前源码修改的隔离副本执行全量 test/build/vet 和相关 race 检查。

真实 Azure 密文兼容和生产部署不属于本地模拟测试可证明的范围。
