# System One 审查记录（2026-09-27）

审查基线：`68386b8`。所有业务数据测试均使用隔离内存数据库，没有操作线上余额。

## 已复现并修复

| 严重度 | 问题及复现 | 修复 |
| --- | --- | --- |
| 高 | 预扣先更新 token、再更新用户；注入用户更新失败后，token 从 100000 降到 99982，用户未扣款。批量模式还会推迟预扣实际落库。 | 采用即时事务及带余额条件的 UPDATE；用户、token 一起成功或一起回滚。 |
| 高 | 注入最终 token 更新失败，仍返回成功、写入 21 quota 消费日志，实际两种余额不同步。 | 余额、用户累计用量、请求次数和渠道用量在同一事务结算。失败返回 500，回滚并退款，禁止网关自动重试。 |
| 高 | 请求进行中将模型改为 $0.5/次，原本应扣 21 quota 的请求实际扣 250000；改变输出倍率也影响在途请求。 | 上游尝试开始时冻结计费类型、输入输出价格与各项折扣。 |
| 中 | 默认倍率 `0.021` 下，3000 输入 token 因浮点误差扣 64，正确值为 63。 | 十进制有理数计算后取整，折扣因子也分别参与精确计算。 |
| 中 | `answers.check: null` 或缺少请求中其他问题答案，仍透传成功并扣费。 | 校验全部问题的答案、类型和基本结果；无效响应返回 502 并退款。 |
| 中 | 零输入、零输出的成功响应没有消费日志，也不增加请求次数。 | 零用量成功照常记录日志和次数，token 模式费用为 0。 |
| 中 | 非 JSON 上游错误产生空 message；204 可能作为“成功状态的错误”返回；后台测试丢失 TypeSafe 的 detail。 | 统一原生错误解析，提供 HTTP 状态兜底，非协议 2xx 转为 502，后台测试保留 detail。 |
| 中 | 429 的 detail 被替换、Retry-After 丢失；亲和配置跳过重试时直接返回，可能成为空 200。 | 保留上游错误说明和 Retry-After；重试成功移除旧头；跳过重试显式输出错误。 |
| 高 | TypeSafe 返回包含特定内容违规文本的 403，会误走通用 Relay 中 xAI 的 $0.05 扣费分支。 | System One 排除 xAI 特殊扣费分支，失败额度为 0，正常记录错误日志。 |

## 边界与限制

验证结果：`go test ./model ./relay/controller ./controller ./router ./middleware ./common` 全部通过；model、relay/controller 的 System One/额度针对性 `-race` 通过；隔离源码目录 `go build ./...`、`go vet ./...` 通过。编译期间有现有 go-sqlite3 C 编译警告，无构建错误。

- 本地事务和并发验证使用 SQLite；生产 PostgreSQL/MySQL 的多实例并发与故障恢复尚未实测。
- 日志库可以与业务库分离，沿用项目日志写入机制，不承诺跨库原子提交。数据库持续不可用时，退款失败会写服务错误日志，需要恢复后对账；本次未引入持久化结算任务系统。
- 修复尚未部署线上。
